# Планировщик задач (Final Project)

Веб-сервер для планирования регулярных и одноразовых задач — бэкенд-часть
приложения TODO-list с готовым фронтендом. Сервер хранит задачи в базе
данных SQLite, умеет вычислять дату следующего выполнения по правилу
повторения и предоставляет REST API для добавления, редактирования,
поиска, отметки о выполнении и удаления задач.

## Описание проекта

Приложение решает задачу планирования: пользователь создаёт задачу с
заголовком, комментарием, датой и (опционально) правилом повторения.
Сервер отображает список ближайших задач, отсортированных по дате, и
после выполнения задачи автоматически переносит её на следующую дату
согласно правилу (либо удаляет, если задача одноразовая).

## Задания со звёздочкой

Выполнены следующие задания повышенной сложности:

- **Полная поддержка правил `NextDate`** — помимо базовых `d` и `y`,
  реализованы правила `w` (дни недели) и `m` (дни месяца, включая
  отрицательные индексы и список месяцев).
- **Поиск задач** — обработчик `GET /api/tasks` дополнительно принимает
  параметр `search`:
  - если значение соответствует формату даты `02.01.2006` (например,
    `08.02.2024`), возвращаются задачи на эту дату;
  - иначе выполняется поиск подстроки без учёта регистра по полям
    `title` и `comment`.
Не реализованы: авторизация по паролю, запуск через Docker, возможность определять путь к файлу базы данных через переменную окружения.

## Запуск локально

### Требования

- Go 1.21+ (проект использует `modernc.org/sqlite`, поэтому CGO не требуется).

### Переменные окружения

Сервер читает порт из переменной окружения `TODO_PORT`. Если она не
задана, используется порт `7540` по умолчанию.

Пример файла `.env` (опционально, если вы используете какой-либо
загрузчик `.env`, либо просто экспортируйте переменную вручную):

```env
TODO_PORT=7540
```

### Запуск

```bash
git clone https://github.com/akross26/final-project.git
cd final-project
go mod tidy
go run main.go
```

При первом запуске автоматически создаётся файл базы данных
`scheduler.db` в корне проекта со всеми необходимыми таблицами и
индексами.

После запуска откройте в браузере:

```
http://localhost:7540
```

Если переменная `TODO_PORT` не задана, адрес будет тем же — сервер
использует порт `7540` по умолчанию.

## Запуск тестов

Тесты находятся в директории `tests` и проверяют работу API поэтапно.

Перед запуском откройте файл `tests/settings.go` и убедитесь, что
установлено:

```go
var FullNextDate = true
```

Это включает проверку правил `w` и `m` в тесте `TestNextDate`, так как
в проекте они реализованы полностью.

Запуск всех тестов:

```bash
go test ./tests
```

Запуск отдельных тестов по шагам:

```bash
go test -run ^TestNextDate$ ./tests
go test -run ^TestAddTask$ ./tests
go test -run ^TestTasks$ ./tests
go test -run ^TestDone$ ./tests
go test -run ^TestDelTask$ ./tests
```

> Перед запуском тестов убедитесь, что сервер не запущен на том же
> порту в отдельном процессе, если тесты сами поднимают сервер —
> либо, наоборот, что сервер запущен, если тесты обращаются к уже
> работающему инстансу (см. комментарии в `tests/settings.go`).

## Запуск через Docker

Docker-образ для проекта не готовился — приложение запускается напрямую
через `go run main.go` или собранный бинарник (`go build -o server .`
с последующим `./server`).
